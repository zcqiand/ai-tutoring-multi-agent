# AI 学习辅导多智能体系统 — 功能规格文档

> 本文档描述 AI 学习辅导多智能体系统 的所有功能特性、验收标准与测试策略。
> 与 [CLAUDE.md](../CLAUDE.md) 共同构成本仓的完整规范文档。

## 功能清单

### 学习路径规划（Planner Agent）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 学习路径制定 | 根据用户问题生成结构化分步大纲（导数定义 → 几何意义 → 求导法则 → 应用） | 输出包含 3 个以上步骤的 JSON 路径，步骤间有依赖关系 |
| 多知识点覆盖 | 能处理数学、物理等跨学科问题 | 给定「请教我导数」时，路径包含定义/几何/法则/应用四步 |
| 上下文记忆 | 本次会话内路径规划结果保留在 shared_memory | orchestrator 打印路径时不出现空引用 |

### 辅导讲解（Tutor Agent）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 分步讲解 | 按 planner 生成的路径逐一步骤讲解 | 每个步骤有独立输出段落，非一次性全量输出 |
| 多轮追问响应 | 学生在某一步有疑问时，tutor 能针对性解答 | 追问内容与当前步骤语义相关（不可答非所问） |
| 模型降级 | 简单讲解任务自动降级到 haiku-4-5，复杂规划用 sonnet-4-6 | cost_tracker 备注中记录实际使用模型 |
| 禁止裸调用 | 所有 API 调用必须经过 cost_tracker 包装 | 代码中不存在 `client.messages.create()` 直接调用 |

### 学习效果评估（Evaluator Agent）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 理解度打分 | 输出 0-100 理解度分数及改进建议 | 同一问题多次评估结果在合理波动范围内（±10） |
| 改进建议生成 | 针对理解薄弱环节给出具体学习建议 | 建议非空字符串，最少包含一条可执行建议 |
| 评估不规划 | evaluator 不调用 planner 的规划逻辑 | 代码审查确认 evaluator agent 无 planner 调用路径 |

### 出题与批改（Question Maker + Grader）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 选择题生成 | 根据知识点和难度生成 4 选项题目 | 输出包含题目文本 + 4 个选项 + 正确答案标识 |
| 答案批改 |对学生提交的答案进行打分和个性化反馈 | 正确/错误答案反馈内容有语义差异 |
| 错题本记录 | 错题自动记录到 student_tracker | JSON 文件中错题记录条数递增 |

### 苏格拉底式辅导（Socratic Tutor）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 引导式提问 | 不直接给答案，以提问引导思考 | 连续 3 次回复中不出现完整结论句 |
| 自适应追问深度 | 根据学生响应调整追问次数 | 不在单次交互中连续追问超过 5 轮 |

### 学生追踪（Student Tracker）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 掌握度追踪 | 记录每个知识点的掌握分数 | 同一知识点两次评估结果可比较（有变化记录） |
| JSON 持久化 | 学生数据保存到本地 JSON 文件 | 重启进程后 `load` 能恢复全部追踪状态 |
| 自适应推荐 | 基于掌握度推荐下一个知识点 | 推荐的知识点的当前掌握度 < 已掌握知识点 |

### 代理间通信（Shared Memory）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 上下文传递 | planner / tutor / evaluator 三者之间显式传递上下文 | shared_memory 实例在 orchestrator 调度链路中可见 |
| 学习轨迹追踪 | 记录完整的学习过程（提问 → 讲解 → 评估） | 三方调用后 shared_memory 中有完整调用链记录 |

### Token 经济学（Cost Tracker）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 实时消耗追踪 | 记录每次 API 调用的 input/output token 数量与费用 | 单次 demo 后输出包含 planner/tutor/evaluator 的分项 token 报表 |
| 预算硬上限 | 总费用超出 $0.50 时 orchestrator 中止并报告 | 调用 `python run_demo.py` 触发超限时进程返回非零 exit code |
| 禁止裸调用 | 所有 `client.messages.create()` 必须经过 cost_tracker | 代码搜索无裸调用模式 |

### 主调度（Orchestrator）

| 功能名称 | 功能描述 | 验收标准 |
| :--- | :--- | :--- |
| 三代理协作调度 | 按顺序调用 planner → tutor → evaluator | `python run_demo.py` 输出中三个代理标签按序出现 |
| 异常中止与报告 | 任一代理异常时打印错误并退出 | 模拟 API 失败场景 orchestrator 输出错误信息并 exit 1 |
